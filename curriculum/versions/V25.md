# V25 — Vision operations and graduated release

## Goal

Operate vision models as versioned production components with drift detection,
controlled promotion, rollback, and continuing evaluation.

## Prerequisites

V24 shadow evidence and approved rights/security review.

## Implementation tasks

1. Register model, data, code, configuration, calibration, and runtime versions.
2. Define offline, shadow, canary, and release promotion stages.
3. Monitor input/confidence drift, sampled identity precision, latency, resource
   use, and unknown rate.
4. Build a privacy-aware hard-example review and annotation loop.
5. Test model rollback, schema compatibility, and text-only fallback.
6. Define uncertainty UX and incident response.
7. Publish a model card and release decision record.

## Required artifacts

- Model registry metadata and lineage
- Promotion policy and automated gates
- Vision operations dashboard and alerts
- Canary/rollback drill
- Model card, incident runbook, and release decision

## Metrics

Gate pass rate, drift indicators, sampled identity precision, false labels per
game, unknown-rate shifts, rollback time, incident detection time, annotation
turnaround, and lineage completeness.

## Failure injection

Bad model promotion, incompatible schema, calibration regression, new uniform,
latency regression, missing artifact, corrupted cache, and rollback during an
active viewing session.

## Acceptance criteria

No model reaches users without reproducible offline evidence, successful shadow
evaluation, passed canary gates, and a tested rollback. A production incident
can disable vision while preserving fantasy scoring and the text HUD.

## Status

Not started. Completion means controlled operation, not that vision is solved.
