# V22 — Real-time vision runtime

## Goal

Turn independently correct stages into a bounded, observable, hardware-aware
real-time graph.

## Prerequisites

V14–V21 stage implementations and measurements.

## Implementation tasks

1. Build bounded asynchronous queues with timestamps and explicit drop policy.
2. Detect at a measured cadence, track between detections, and schedule jersey
   work only for promising crops.
3. Compare PyTorch and ONNX Runtime; test TensorRT FP16 where hardware permits.
4. Introduce INT8 only with representative calibration data and accuracy checks.
5. Instrument decode, copies, preprocessing, inference, association, identity,
   serialization, and rendering boundaries.
6. Run complete-game soak and resource-contention tests.

## Required artifacts

- Runnable pipeline CLI or service
- Stage latency traces and queue metrics
- Hardware/runtime comparison
- Full-game soak and degradation report

## Metrics

Capture-to-output p50/p95/p99, frame age, stage latency, throughput, dropped
frames, queue depth, longest stall, VRAM/RAM, CPU/GPU utilization, power where
available, and accuracy change after optimization.

## Failure injection

Slow decoder, GPU contention, bursty input, oversized frames, model warm-up,
broker slowdown, memory pressure, and one stage running below real time.

## Acceptance criteria

The graph meets latency/resource gates for a full game with no unbounded queue
growth and no unacceptable identity-quality regression.
