# V24 — Permitted live shadow mode

## Goal

Run the vision system against a permitted live or near-live source without
showing identity claims to users, then compare predictions with reviewed truth.

## Prerequisites

V23 replay integration, a documented permitted capture path, and passed V21–V22
safety and latency gates.

## Implementation tasks

1. Document source authorization, capture latency, resolution, and failures.
2. Run detections, tracks, and identity beliefs in shadow mode.
3. Sample decisions and disagreements for human review.
4. Use play-by-play as supporting context, never visual ground truth.
5. Measure drift from the offline corpus and identify missing scenarios.
6. Exercise an immediate kill switch and text-only fallback.

## Required artifacts

- Live-source boundary and authorization record
- Multi-session shadow-run report
- Reviewed disagreement set
- Kill-switch/fallback drill and go/no-go recommendation

## Metrics

Live identity precision estimate with confidence intervals, reviewed coverage,
source-to-overlay latency, capture failures, scenario drift, false labels,
unknown rate, and review load.

## Failure injection

Capture interruption, bitrate/resolution change, clock skew, new graphics or
uniforms, weather, overtime, provider outage, and worker failure.

## Acceptance criteria

Multiple live shadow runs meet predeclared gates, the kill switch works, and all
critical disagreements are understood or explicitly deferred.

## Status

Not started. Shadow mode does not authorize user-visible deployment.
