# V5 — Reliable processing

## Goal
Make repeated delivery boring.

## Prerequisites
Idempotency, ordering, retries, dead letters; complete V4.

## Lessons
Add inbox, dedupe, sequence policy, dead letter.

## Implementation tasks
1. Write a design note before code.
2. Keep external inputs behind a boundary.
3. Add a credential-free fixture or test.
4. Update diagrams/ADRs when boundaries change.
5. Label incomplete work honestly.

## Lab
Process-once and projection rebuild.

## Failure injection
Duplicate, out-of-order, poison, transient failure.

## Acceptance criteria
Two runs produce one projection and audit trail.

## Checkpoint questions
What guarantee does dedupe provide?

## Stretch goal
Reconciliation job.

## Deepen your understanding
Read learning/modules/distributed-systems.md and the guided lab in
learning/notes/v5-reliable-processing-lab.md. Complete at least four
failure-injection exercises, answer the checkpoint questions, and add a dated
source plus one experiment result to learning/REFERENCES.md.

## Further reading placeholders
Official docs; one design paper; one postmortem; one experiment note.

## Status
Implemented as an in-memory reliable-processing lab. Duplicate deliveries are
deduplicated by event ID, out-of-order input is ordered by cursor, poison events
are dead-lettered, transient failures retry with a limit, and outcomes are
audited. Durable persistence, distributed workers, and production exactly-once
claims remain deferred.
