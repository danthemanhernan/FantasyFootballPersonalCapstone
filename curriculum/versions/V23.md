# V23 — Replay-to-HUD vision integration

## Goal

Replay recorded vision decisions through the real event and broker path into a
synchronized browser overlay.

## Prerequisites

V22 runtime, V21 identity decisions, and the authenticated Redis/WebSocket HUD.

## Implementation tasks

1. Define versioned vision marker snapshot/delta contracts.
2. Publish replay events with source timestamps and idempotency keys.
3. Scope streams to authorized users, games, and viewing sessions.
4. Map source coordinates into the actual video content rectangle.
5. Reconnect with a marker snapshot and reject stale/out-of-order deltas.
6. Correlate marker, canonical play, and fantasy scoring events without making
   one source falsely prove another.

## Required artifacts

- Replay publisher and broker topic
- Authenticated marker WebSocket flow
- Browser replay demonstration
- End-to-end trace and reconnect/order tests

## Metrics

Publish-to-render and capture-to-render latency, stale/out-of-order drop rate,
reconnect recovery, synchronization error, anchor error, and render cost.

## Failure injection

Duplicates, delayed deltas, reconnects, resize/fullscreen, stale snapshots,
wrong users, out-of-order sequences, and replay speed changes.

## Acceptance criteria

A deterministic recorded experiment replays through production-like transport
and renders the same correctly aligned decisions after disconnect and reconnect.
